## Goal

Let a milestone provide a concise presentation summary for compact public surfaces without weakening its full deliverable description.

## Problem

The Overview milestone section currently renders the milestone's complete deliverable description. That contract is appropriate in milestone details, but substantial Outcome, Scope, Exclusions, and Evidence content can dominate a landing page or create poor split-layout balance. Project Model happens to balance against its long introduction, but other projects need a deliberate shorter narrative.

## Proposed behavior

- Add an optional milestone summary alongside the existing deliverable description.
- Keep the description authoritative for the complete deliverable contract.
- Have the Overview milestone section render the summary when present and fall back to the full description for existing projects.
- Carry the resolved summary through current, linked-project, embedded, and static Overview contracts.
- Expose the field through the established milestone mutation surfaces rather than requiring routine direct YAML edits.
- Preserve projects without summaries without migration churn.

## Acceptance criteria

- An authored summary is shown on the Overview milestone card while milestone details retain the full description.
- Missing summaries preserve today's Overview output.
- Validation rejects invalid configured values with an actionable diagnostic.
- CLI, API, MCP, and Settings behavior remain consistent with milestone ownership boundaries.
- Focused resolver, contract, static-snapshot, and Angular presentation tests cover both summary and fallback behavior.
