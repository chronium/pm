## Goal

Prove the complete linked-project milestone activation toolset across reads, definition changes, trigger lifecycles, delivery, recovery, and capability boundaries.

## Scope

- Add end-to-end fixtures containing current, parent, child, unavailable, ambiguous, readable-untrusted, and write-trusted projects.
- Exercise selected-project reads, milestone and trigger definition mutations, activation transitions, reconciliation, delivery previews, delivery, and reopening through real stdio MCP clients.
- Verify automatic activation caused by cross-project task mutation is persisted in the task's owning project and immediately visible through selected-project reads.
- Verify duplicate task, milestone, and trigger keys remain isolated by owning project.
- Cover target disappearance, binding mismatch, stale revisions, rejected cycles, partial filesystem recovery, and reconciliation after repository edits.
- Exercise the normal trusted profile and the restricted run-worker profile, including tool advertisement and direct invocation guards.
- Verify mutation receipts, changed paths, owner metadata, warnings, authoritative rereads, and linked-family recommendation effects.
- Update MCP, CLI, linked-project, and activation documentation with selector, trust, recovery, and operational examples.
- Run the complete .NET and release gates and perform a preserved linked-project dogfood smoke.

## Acceptance criteria

- Every cross-project activation and delivery tool has deterministic success and failure coverage.
- Failed preflights and stale revisions leave all family repositories unchanged.
- Every successful mutation writes only the selected repository and reports its stable project ID.
- Current-project behavior remains compatible when `project` is omitted.
- Run-worker clients can read only the current switchboard and cannot access any control-plane mutation.
- Documentation clearly distinguishes readability, write trust, control-plane authorization, and project ownership.
- `pm doctor`, the complete .NET suite, frontend/release validation, and the linked-project dogfood smoke pass.

## Out of scope

Family-wide aggregate switchboards remain deferred until dogfooding establishes a concrete consumer and presentation model.
