## Goal

Make Action ref promotion resilient to GitHub's short read-after-create and read-after-update propagation delays without weakening immutable-ref, smoke-gate, or rollback guarantees.

## Implement

- Add a small bounded consistency wait around post-mutation ref verification in `github-action/release/promote-ref.sh`.
- Retry only transient absent or stale reads after a successful create or update.
- Continue failing immediately when an immutable ref already identifies a different commit.
- Keep channel rollback provenance and `previous-target` output exact.
- Add deterministic tests using a controlled fake `gh` command for delayed creation visibility, delayed channel updates, conflicts, timeout, and rollback behavior.
- Exercise the helper from the Action release-policy validation gate.

## Acceptance criteria

- Creating a new immutable release ref or compatible-major channel does not fail solely because GitHub's subsequent read is briefly stale.
- A wrong immutable target, a persistent mismatch, or a failed mutation still stops promotion.
- `latest` and `vMAJOR` rollback behavior remains unchanged when downstream smoke fails.
- Tests reproduce the `v1.1.0` and first-`v1` propagation failure observed during the 1.1.0 release.
- The complete Action release-policy checks pass.
