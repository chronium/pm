## Goal

Replace current wiki pages with a routed Angular wiki shell, tree, reader, editor, and metadata workflow.

## Implementation

- Build a wiki feature store with signals and `httpResource`, using the generated API types and handwritten API client.
- Render the complete directory/page tree in `WikiShell`; folders expand/collapse and folder-only routes show their descendant listing rather than a missing-page error.
- Preserve navigational URLs under `/wiki`, with `/wiki/new` ordered before the catch-all page route.
- Render page Markdown with marked and DOMPurify using the shared Markdown display component.
- Implement create, body-only EasyMDE edit, explicit path/title metadata edit, and confirmed delete.
- Keep frontmatter hidden and preserve service-owned timestamps/metadata.
- Use page ETags for edits, rename, and deletion.
- Keep MCP-only outline/patch operations and wiki search out of this parity slice.
- Preserve breadcrumbs, direct links, responsive tree navigation, loading/error/empty states, and keyboard accessibility.

## Acceptance

- Index, folder, page, create, edit, rename, and delete flows work on direct navigation and refresh.
- Wiki paths and user-controlled content are encoded/sanitized safely.
- Long pages and editor views scroll correctly.
- Vitest and Playwright cover tree navigation and critical mutations.
