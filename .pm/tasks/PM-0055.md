## Goal

Reduce the routed task board to a feature coordinator by moving its distinct rendering responsibilities into focused Angular components before more task-board behavior is added.

## Implementation

- Keep `TasksBoard` responsible for route integration, the route-scoped `TasksBoardStore`, loading/error/empty orchestration, refresh feedback, and the nested task outlet.
- Extract the filter toolbar into a task-board filter component. Give it typed signal inputs for options and active filters, and explicit outputs for changing and clearing filters.
- Extract milestone sections, collapsible status groups, and task rows into focused components with typed generated-API inputs.
- Keep collapse persistence and URL mutation in the feature store or routed coordinator; presentation components emit intent rather than injecting routing or application services.
- Keep task rows semantic links, preserve selected-route state and query parameters, and retain the established dense responsive layout, surface hierarchy, badges, focus behavior, and accessibility.
- Move component-specific CSS beside each component. Keep only board composition and page-level state styling in the routed board stylesheet.
- Avoid generic configuration-heavy components. Extract around stable responsibilities and compose the task feature from small standalone Angular components.
- Add a repository rule to `AGENTS.md`: routed feature components should coordinate data, routing, and page state; repeated or independently meaningful UI regions should be focused components with typed inputs/outputs rather than accumulating in one page template. Trivial one-off markup does not require extraction.

## Tests

- Add focused Vitest coverage for filter events, milestone/status rendering and collapse intent, task-row metadata and route links, selected state, long content, and accessible names.
- Keep routed board tests focused on store integration, loading/error/empty states, filter wiring, nested selection, and composition.
- Verify the production board remains visually unchanged at desktop and mobile widths.

## Acceptance

- The routed board no longer directly renders filter controls, milestone/status internals, or task-row internals.
- Child components do not fetch data or duplicate board business logic.
- Existing board behavior and visual styling remain intact.
- `npm run check`, `npm test`, and `npm run build` pass.
