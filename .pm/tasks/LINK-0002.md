## Goal

Add a versioned committed manifest for declaring one optional parent and an ordered list of child projects without changing standalone project behavior.

## Proposed implementation

- Add typed models and structured YAML persistence under .pm.
- Store stable project ID, local alias, repository URL, relationship, and optional relative path hint.
- Validate aliases, duplicate IDs, malformed paths, and the one-parent constraint.
- Keep existing projects valid when the manifest is absent.
- Expose application-service operations for listing and maintaining declarations.

## Acceptance criteria

- Standalone projects require no migration.
- Manifests round-trip deterministically and remain human-readable.
- Invalid declarations produce bounded validation results.
- No declaration grants write trust or causes filesystem scanning.
