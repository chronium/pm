## Goal

Prevent ordinary stale browser writes while allowing CLI, MCP, and web workflows to continue sharing the filesystem.

## Implementation

- Produce strong quoted ETags for board representations, individual task persistence state, individual wiki pages, and project configuration.
- Support `If-None-Match` on reads and return `304 Not Modified` where appropriate.
- Require `If-Match` for update, delete, state-change, metadata, and reorder operations; return `428 Precondition Required` when absent and `412 Precondition Failed` when stale.
- Do not require a precondition for create operations.
- Compute task revisions from the persisted task content and state, wiki revisions from persisted page content, config revisions from persisted configuration, and board revisions from the filtered board representation.
- Perform revision checks immediately before calling the existing mutation service.
- Treat this as best-effort cross-process protection. Do not add filesystem locking or claim full transactions across separate CLI/MCP/web processes.
- Return the current revision with successful resource responses so Angular can continue without an unnecessary reload.

## Acceptance

- Tests cover matching, stale, missing, and conditional-read headers for each resource class.
- Unrelated task or wiki edits do not invalidate resource-specific editor revisions.
- Board ETags vary with filters and board-visible changes.
- Existing direct service callers require no revision argument.
