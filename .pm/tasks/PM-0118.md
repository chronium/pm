## Goal

Produce the small Linux OCI runtime that executes the released PM CLI inside the reusable GitHub Action.

## Implement

- Reuse the validated framework-dependent `artifacts/release` payload produced by the existing PM release gate.
- Build from a pinned .NET 10 ASP.NET Alpine base for Linux amd64 and arm64.
- Copy only the portable PM assemblies, runtime metadata, localized resources, and embedded Angular assets; exclude the host-specific apphost, symbols, source trees, package caches, and development SDKs.
- Run PM through `dotnet /opt/pm/PM.dll` from `/github/workspace` with invariant globalization and quiet, non-diagnostic .NET runtime settings.
- Keep `/opt/pm` read-only and add OCI source, version, revision, and creation metadata.
- Add local container checks for image contents, labels, version reporting, project validation, failure diagnostics, and static export persistence.
- Produce a native local image plus a multi-platform OCI archive and report reproducible local identity evidence. Registry publication and the authoritative manifest digest belong to PM-0121.

## Acceptance criteria

- A native image runs raw PM `--version`, `doctor`, and `site build` invocations against disposable mounted projects.
- Static output written beneath the mounted workspace remains available on the host.
- Invalid projects fail with useful PM diagnostics and do not leave static output behind.
- The final runtime contains no build credentials, host-specific apphost, symbols, or unnecessary development tooling.
- Automated checks inspect the exact published layout, OCI labels, root user, working directory, and entrypoint.
- A multi-platform OCI archive contains Linux amd64 and arm64 manifests and its checksum is reported without presenting it as a published registry digest.
- Command allowlisting, Action inputs and outputs, workspace path policy, and the public `action.yml` remain scoped to PM-0119 and later release tasks.
