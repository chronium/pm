## Goal

Provide detailed audit history beyond recent-change summaries.

## Proposed implementation

- Build on the mutation log introduced for recent changes.
- Include timestamp, tool or command name when known, actor/session when available, target object, operation type, and summary.
- Add filters for target type, target ID/path, and limit.
- Expose through MCP as `get_audit_log`.

## Acceptance criteria

- Agents can inspect detailed mutation history.
- Filtering by target narrows results.
- Entries remain structured and stable across tool callers.
- Unknown actor/session values are represented explicitly rather than guessed.

## Validation notes

- Add service and MCP tests for filtering, ordering, empty logs, and representative logged operations.
