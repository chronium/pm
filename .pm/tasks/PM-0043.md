## Goal

Expose current web board and task workflows through `/api/v1` using the existing board and task services.

## Implementation

- Add a board read endpoint supporting the existing track, milestone, and state filters and returning project options, milestone/state groups, task summaries, dependency state, priorities, and the board ETag.
- Add task detail, create, structured update, state change, and remove endpoints.
- Preserve current web-editable fields: title, description, state, and priority. Task track/milestone editing and bulk operations remain out of scope.
- Return `201 Created` with a location and task revision after creation.
- Apply task ETags to structured update, state change, and removal.
- Keep next-ID allocation and all validation in `TaskService`.
- Keep absolute file paths only where current web parity requires them; mark them as local metadata rather than identifiers.
- Map missing and invalid tasks, states, tracks, milestones, priorities, and next-ID failures through the shared Problem Details contract.

## Acceptance

- Endpoint tests cover filtered boards and all task success/failure paths.
- Representative responses conform to generated OpenAPI types.
- Creating or mutating a task immediately returns enough data for Angular to update and then refresh the active board.
- No bulk MCP-only behavior is added to the API.
