## Goal

Turn the Angular task sidebar into the primary navigation and filtering surface for tracks and milestones, while improving the readability of the all-milestones board.

## Proposed implementation

- Populate the task sidebar with the project milestones and tracks from the existing board/settings data.
- Keep `All tasks` as the whole-project entry and add clear active states for selected milestone and track routes.
- Move milestone and track filtering out of the board toolbar; keep status filtering in the board for this slice.
- Represent sidebar selections through the existing route query parameters so refresh, deep links, task dialogs, search navigation, polling, and browser history preserve context.
- Show useful remaining-task counts beside sidebar entries without making navigation visually noisy.
- Keep the sidebar dense, keyboard accessible, and usable through the existing mobile navigation behavior.
- Add a small vertical gap between milestone groups when the board displays all milestones so adjacent groups no longer touch.
- Keep the existing task rows, state groups, and board surface styling otherwise unchanged.
- Extract focused sidebar/navigation components where needed instead of growing the task shell or board page.

## Acceptance criteria

- Users can select all tasks, one milestone, or one track from the task sidebar.
- The selected sidebar entry is visibly active and exposes the correct accessible current state.
- Milestone and track dropdowns no longer consume board content space.
- Status filtering continues to work and composes with the selected sidebar scope.
- Route query parameters and browser navigation preserve the selected scope.
- Search and task-dialog navigation retain the current board scope.
- Milestone groups have subtle, consistent separation when multiple milestones are visible.
- Desktop and mobile sidebar workflows remain keyboard accessible and responsive.
- Loading, empty, error, and zero-count states do not break the sidebar layout.

## Validation notes

- Add component and integration tests for sidebar rendering, active states, counts, selection, query-parameter preservation, and mobile behavior.
- Add board tests covering milestone spacing and combined sidebar/status filters.
- Add or update Storybook stories for realistic long milestone/track lists and active states.
- Run Angular formatting, type checks, unit tests, Storybook tests, production build, and relevant E2E flows.
