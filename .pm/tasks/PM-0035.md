## Goal

Create CLI and web analogs for the planned `list_recent_changes` MCP workflow.

## Proposed implementation

- After the mutation log exists, add `pm recent [--limit]` or similar CLI command.
- Add a read-only recent changes section in web, likely settings/project health or a small sidebar/index surface.
- Use the same recent-change query service as MCP.
- Keep this as summary-level history, not the full audit log.

## Acceptance criteria

- CLI, web, and MCP show the same recent changes ordering.
- Missing log renders an empty state.
- Entries include timestamp, operation, target, and summary.
- Logging failures do not block primary operations.
