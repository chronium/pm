## Goal

Create CLI and web analogs for the planned `get_audit_log` MCP workflow.

## Proposed implementation

- After audit logging exists, add `pm audit` with limit and target filters.
- Add an audit log view under web settings or project health.
- Use the same audit query service as MCP.
- Keep audit entries read-only.

## Acceptance criteria

- CLI and web can inspect detailed audit history.
- Filters by target type/path/id work consistently.
- Unknown actor/session values are displayed explicitly.
- Recent changes remains the concise summary surface.

## Validation notes

- Add command, endpoint, renderer, and service tests for filtering, ordering, and empty logs.
