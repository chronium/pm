## Goal

Give PM one authoritative delivered-work visibility rule for task and milestone discovery across local and linked reads.

## Proposed implementation

- Extend the shared board and task-search read options with `includeDelivered`, defaulting to `false`.
- Resolve delivered status from the explicit milestone lifecycle; do not infer it from task state or completion percentage.
- Exclude tasks assigned to delivered milestones before board grouping, navigation counts, task-list truncation, and search ranking.
- Exclude delivered milestone options from work-discovery milestone lists while retaining every configured track.
- Add `--include-delivered` to CLI task list, task search, and milestone list commands.
- Add optional `includeDelivered` parameters to MCP `list_tasks`, `search_tasks`, and `list_milestones`.
- Apply the same behavior to current-project, selected linked-project, and family reads.
- Keep direct task reads, next-task recommendation, Settings, activation switchboard, delivery controls, and Overview resolution unchanged.

## Acceptance criteria

- Local and linked list/search reads omit tasks assigned to an explicitly delivered milestone by default.
- The explicit include option returns those tasks and milestones without changing ordering.
- Delivered milestones with accepted unfinished tasks are hidden by default.
- Reopened milestones become visible without another data migration.
- Unassigned tasks and tasks in active, inactive, or ready-to-deliver milestones remain visible.
- Tracks remain listed even when their visible task count is zero.
- `in:all` changes search scope only and does not include delivered work.
- CLI and MCP contract tests cover defaults, opt-in behavior, linked reads, and direct-read exclusions.
- Relevant .NET build and tests pass.
