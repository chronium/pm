## Goal

Create a repeatable, manually initiated release process that publishes PM as both a .NET global tool and standalone cross-platform command-line archives, with the embedded Angular application included in every distribution.

## Distribution model

- Publish the NuGet tool package as `Chronium.PM` with command name `pm`.
- Use .NET 10 RID-specific, self-contained tool packages for:
  - `osx-arm64`
  - `linux-x64`
  - `linux-arm64`
  - `win-x64`
- Include an `any` framework-dependent fallback package for other .NET 10 platforms.
- Publish equivalent standalone GitHub Release archives:
  - `pm-v<version>-osx-arm64.tar.gz`
  - `pm-v<version>-linux-x64.tar.gz`
  - `pm-v<version>-linux-arm64.tar.gz`
  - `pm-v<version>-win-x64.zip`
- Standalone archives contain `pm` or `pm.exe`, the license, concise installation notes, and no development-only output.
- Do not add AppImage, MSI, Homebrew, or WinGet packaging in this task. Homebrew and WinGet can consume these release archives in later tasks.

## Versioning

- Adopt CalVer in the normalized form `YYYY.M.PATCH`, for example `2026.7.0`.
- Increment `PATCH` for additional releases in the same month.
- Use SemVer-compatible prerelease suffixes such as `2026.7.0-rc.1`.
- Tag releases as `vYYYY.M.PATCH`.
- Replace the hard-coded application version with one authoritative MSBuild version supplied by the release build.
- Ensure `pm --version`, assembly/package metadata, NuGet packages, filenames, tag, and GitHub Release all report the same version.

## Packaging implementation

- Configure PM as a .NET tool with `PackAsTool`, `ToolCommandName=pm`, package metadata, README, repository URL, license expression, and symbol/package settings appropriate for NuGet.org.
- Use RID-specific self-contained CoreCLR packages; do not introduce trimming or Native AOT until compatibility with ASP.NET Core, Spectre.Console, MCP, syntax highlighting, and embedded resources has been proven separately.
- Reuse the existing Angular production build and `EmbedAngularAssets=true` publication boundary.
- Add deterministic archive creation and SHA-256 checksum generation.
- Produce an artifact manifest containing version, commit SHA, RID, archive filename, checksum, and NuGet package names.
- Keep build outputs under ignored `artifacts/` paths.

## Manual release workflow

Add a dedicated GitHub Actions `workflow_dispatch` release workflow, separate from Pages and ordinary validation.

Inputs:

- required CalVer version
- optional target commit, defaulting to the selected `main` workflow ref
- prerelease flag

The workflow must:

1. Validate and normalize the version.
2. Require the target commit to be reachable from `main`.
3. Reject mismatched existing tags, GitHub Releases, or NuGet versions.
4. Run the complete locked release gate before publishing.
5. Build and smoke-test every RID-specific tool package and standalone archive on an appropriate runner.
6. Aggregate artifacts and verify checksums and version consistency.
7. Create the annotated release tag only after validation succeeds.
8. Publish RID packages before the top-level NuGet pointer package.
9. Authenticate to NuGet.org with trusted publishing/OIDC and a protected GitHub `release` environment; do not store a long-lived NuGet API key.
10. Create the GitHub Release and attach archives, checksums, manifest, and NuGet packages.
11. Support safe reruns after partial publication without moving an existing tag or replacing immutable NuGet packages.

The workflow should fail closed if any target artifact is missing or untested. Publication remains an explicit manual action and must never run from an ordinary push.

## Validation

- Pack and install `Chronium.PM` from a local NuGet source, then run `pm --version`, `pm --help`, MCP startup, `pm web`, and static site export.
- Execute equivalent smoke tests against each standalone archive.
- Verify embedded Angular assets are served from every package.
- Verify the `any` fallback package on a framework-dependent test path.
- Test invalid CalVer, duplicate versions, wrong branches, missing artifacts, prerelease behavior, and resumable publication logic without publishing during tests.
- Continue running the existing .NET, Angular, embedded, and static release gates.

## Documentation

- Document installation, update, and removal for the .NET tool and standalone archives.
- Explain supported RIDs, the framework-dependent fallback, CalVer, prereleases, checksum verification, and the manual release procedure.
- Add follow-up notes for Homebrew and WinGet manifests once stable release URLs exist.

## Acceptance criteria

- A maintainer can manually publish one version from a reviewed `main` commit through a single protected workflow.
- `dotnet tool install --global Chronium.PM` installs a working `pm` command on all four primary RIDs.
- Standalone archives run without a preinstalled .NET runtime.
- CLI, MCP, embedded web, and static export behavior match the existing release artifact.
- Every public artifact has a checksum and traceable source commit.
- No AppImage or platform installer is required for the first release.
