## Goal

Replace the current server-rendered board with a dense, routed Angular task workspace.

## Implementation

- Add a task feature store using signals, computed state, generated API types, and `httpResource` for board reads. Do not add NgRx or a global application store.
- Bind track, milestone, and state filters to URL query parameters and send them through the existing server-side `BoardQuery`.
- Render milestone sections and collapsible status groups with task counts. Keep `done` collapsed by default and preserve user toggles for the session.
- Render dense task rows with title, ID, track/milestone context, priority, dependency readiness, and useful description preview without decorative card nesting.
- Navigate task selection to the nested `/tasks/:taskId` route while keeping the board mounted behind the child outlet.
- Preserve stable layout, keyboard navigation, visible focus, loading/error/empty states, responsive task priority, and immediate filter feedback.
- Trigger an explicit board reload after successful task mutations; periodic external-change polling is completed in its dedicated task.

## Acceptance

- Filters survive refresh and browser navigation.
- Large boards remain scannable and do not create accidental horizontal scrolling.
- Status collapse behavior matches current defaults.
- Vitest covers grouping, filtering state, long content, accessibility semantics, and route selection.
