## Goal

Expose the resolved Overview document through the existing revisioned current- and linked-project read boundaries.

## Implement

- Add `GET /api/v1/overview` and `GET /api/v1/projects/{projectId}/overview`.
- Return the same typed document shape for current and readable linked projects.
- Apply established ETag, conditional-read, project reload, access-failure, and API problem conventions.
- Keep disabled and invalid documents as successful typed reads; reserve request failures for access, transport, and unexpected project-read failures.
- Generate and commit the Angular API types through the repository's established script.

## Acceptance

API tests cover ready, disabled, invalid, conditional reads, revision changes, linked-project selection, unavailable or unreadable projects, and absence of file-system or selector details in responses. Run .NET build/tests and API type checks.
