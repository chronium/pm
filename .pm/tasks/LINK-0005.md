## Goal

Represent cross-project task and wiki targets canonically without requiring globally unique task IDs.

## Proposed implementation

- Add typed project-qualified references that persist stable project IDs.
- Preserve existing plain local task dependency strings.
- Accept ergonomic selectors such as parent/second and local aliases at command boundaries.
- Add canonical pm:// project task and wiki URI parsing and formatting.
- Render current local aliases and project names while retaining stable persisted identity.
- Validate malformed references without requiring the target project to be present.

## Acceptance criteria

- Existing task files parse without migration.
- Local and cross-project references are unambiguous.
- Alias or directory changes do not alter persisted identity.
- Task and wiki references round-trip through CLI, MCP, API, and Markdown.
