Follow the Milestone Deliverables and Activation Triggers architecture wiki entry.

## Goal

Let project owners create activation trigger definitions from the Angular Activation settings surface without falling back to the CLI.

## Scope

- Add a focused trigger-creation dialog with an immutable key, editable title, and zero or more task or milestone requirements.
- Provide a reusable, search-backed requirement editor that selects valid local task and milestone sources and excludes duplicate selections.
- Treat an empty requirement list as an intentional manual-only trigger and explain that consequence before saving.
- Adopt the revisioned mutation response immediately and refresh project settings so milestone trigger choices stay current.
- Use existing dialog, dirty-state, revision conflict, problem details, project refresh, and external-change patterns.

## Acceptance criteria

- Owners can create a trigger containing task requirements, milestone requirements, both kinds, or no requirements.
- Task selection is search-backed for realistic projects; milestone selection is filterable; selected requirements are removable and cannot be duplicated.
- Manual-only creation is explicit before submission.
- Mutation success refreshes the switchboard and milestone trigger choices without losing the current Settings section.
- Stale revisions, validation failures, unavailable sources, and duplicate keys produce localized actionable errors without discarding the draft.
- Read-only and static projects expose no creation control.
- Keyboard order, visible focus, accessible names, dialog dismissal, mobile layout, and reduced-motion behavior follow existing UI patterns.
- Component, store, Storybook, and focused browser tests cover creation, selection, manual-only behavior, conflicts, and read-only behavior.
