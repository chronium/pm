## Goal

Let people reveal delivered history from the task page without allowing historical milestones to dominate the default board or sidebar.

## Proposed implementation

- Add a compact **Show delivered** toggle below **Next task** and before the scrollable scope region.
- Keep the toggle available in writable, read-only, embedded, and static task pages.
- Represent the enabled state as `includeDelivered=true` in the task-page URL; absence remains the default hidden state.
- Retain the setting through the existing per-project session filter memory and project switching.
- Forward the same value to board, navigation, polling, and task-search requests.
- When the toggle is switched off while a delivered milestone is selected, clear that milestone selection and return to the unscoped board.
- Use a native button with `aria-pressed`, a clear accessible name, visible focus, and a practical touch target.
- Preserve all configured track navigation even when a track has no visible work.
- Extend static-mode request adaptation, Storybook fixtures, and end-to-end workflows as required by the UI behavior.

## Acceptance criteria

- Fresh task pages omit delivered milestone links, board groups, assigned tasks, and search results.
- Enabling **Show delivered** restores them without reloading the application or losing unrelated track/state filters.
- Disabling it from a delivered milestone scope returns to **All tasks** without an empty or invalid selection.
- Search respects the toggle even when the query uses `in:all`.
- The setting is isolated per project and survives task/wiki navigation within the session.
- Live and static read-only pages expose the same control and results.
- Keyboard, screen-reader, desktop, mobile, loading, empty, and error behavior is covered.
- Visual review occurs after focused validation and before the release gate, task completion, or final commit.
- The complete frontend and release gates pass after approval.
