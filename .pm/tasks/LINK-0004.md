## Goal

Make linked-project health visible while guaranteeing that unavailable family members cannot break the active project.

## Proposed implementation

- Add resolution statuses for available, unregistered, missing, uninitialized submodule, identity mismatch, invalid, and untrusted-for-write.
- Detect parent cycles, duplicate aliases, duplicate IDs, non-reciprocal declarations, and traversal limits.
- Treat reachable topology defects according to severity and report unavailable projects as warnings.
- Extend doctor, CLI results, MCP responses, and API contracts with bounded warnings.
- Test the maximum 32-project, depth-two family traversal policy.

## Acceptance criteria

- Local project validation succeeds when optional linked projects are absent.
- Non-reciprocal links remain usable with warnings.
- Family operations return partial results and named warnings.
- Existing standalone tests remain unchanged in behavior.
