Follow the Milestone Deliverables and Activation Triggers architecture wiki entry.

Add milestone delivery and reopening application workflows and CLI commands.

Acceptance criteria:
- Ordinary delivery requires all assigned tasks done.
- Exceptional delivery requires confirmation, a reason, and a snapshot of accepted unfinished task IDs.
- Delivery records use only publish-safe actor metadata.
- Reopening removes delivery provenance and re-evaluates required triggers.
- Delivered milestones dominate current trigger state.
- Partial write failures restore prior milestone state.
- Tests cover ordinary, exceptional, empty, inactive, and reopened milestones.
