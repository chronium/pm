## Goal

Update project-level metadata without recreating the project.

## Proposed implementation

- Add a modeled project update service that can change safe config fields such as project name and future metadata fields.
- Keep ID settings conservative; avoid changing ID prefix/width if doing so would break existing task IDs.
- Expose through MCP as `update_project`.
- Return the updated project payload.

## Acceptance criteria

- Project name can be updated and persisted.
- Unsupported or unsafe fields fail clearly.
- Existing project ID and task data remain unchanged.
- `get_project` reflects successful updates.

## Validation notes

- Add service and MCP tests for updating project name, rejecting unsafe ID changes, missing project behavior, and payload consistency.
