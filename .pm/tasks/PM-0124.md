## Goal

Replace PM's hard-coded product version with one authoritative, machine-readable release identity shared by the CLI, .NET build, OCI runtime, and GitHub Action.

## Implement

- Adopt PM's altered semantic version contract: major is an explicit compatibility decision, minor represents an accepted milestone deliverable, and patch represents one completed task.
- Persist one canonical `major.minor.patch` value for the PM repository and seed it through an explicit cutover without retrospectively counting historical work.
- Replace the hard-coded application version and duplicate release literals with build metadata derived from that source.
- Stamp `pm --version`, .NET assembly metadata, OCI labels, Action `pm-version` output, and release records with the same exact version.
- Keep repositories that do not opt into release versioning unchanged.
- Reject malformed, missing, or contradictory publish-time version data instead of silently emitting an ambiguous release.
- Document why PM uses delivery-oriented patch/minor semantics rather than CalVer or strict bug-fix-only SemVer.
- Define how these bootstrap tasks are counted exactly once while the automatic advancement mechanism is being introduced.

## Acceptance criteria

- A single authoritative version is visible consistently through the CLI, packaged assembly, OCI metadata, Action output, and release evidence.
- PM's current public version has an explicit, reviewable migration into the new source of truth.
- Local development remains usable, while publishable builds cannot fall back to an unstamped or conflicting version.
- Existing PM projects without versioning configuration retain their current behavior.
- Major-version advancement is never inferred or automatic.
- Tests cover canonical parsing, invalid data, build stamping, and cross-surface version agreement.
