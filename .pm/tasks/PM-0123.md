## Goal

Adopt the already dogfooded `chronium/pm@latest` Action across the ChronoFall family without exposing direct PM image or installation details to the consumer workflow.

## Implement

- Checkout the ChronoFall family with the linked repositories required for publishing.
- Run `command: doctor` for every project included in the published family.
- Run `command: site-build` for each project into stable, non-colliding deployment paths.
- Upload and deploy the combined Pages artifact using the repository-owned deployment workflow.
- Preserve independently rendered PM sites and the normal in-PM project switcher rather than creating a combined dashboard.
- Verify root README links and project-switcher targets against the deployed path layout.
- Record the floating-`latest` ownership decision and a rollback procedure to an immutable PM Action version.
- Add a concise example for future PM repositories that want validation, static export, or both.

## Acceptance criteria

- ChronoFall workflows do not invoke the OCI image or install PM directly.
- Invalid PM project data stops publishing before artifact deployment.
- Every family project opens at its intended URL and switches to the other published projects correctly.
- A known-good immutable Action ref can replace `@latest` during rollback.
- The workflow consumes the same Action release already proven by PM's own site publication.
- The dogfood workflow demonstrates the minimal supported setup for another PM-based repository.
