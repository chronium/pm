## Goal

Allow Kestrel to serve either the legacy UI or the built Angular application while keeping API-only development independent.

## Implementation

- Add `pm web --api`; it binds loopback, defaults to port `51237`, maps only `/api/v1` and OpenAPI endpoints, and does not open a browser.
- Add temporary `pm web --ui <legacy|angular>`. Default to `legacy` during migration; the cutover task will switch the default.
- Embed the production Angular browser build into the .NET assembly. Do not commit `dist/`.
- Serve fingerprinted static assets with correct MIME/cache headers, serve `index.html` without immutable caching, and use SPA fallback only for non-API routes.
- Fail clearly when Angular mode is requested but embedded assets were not built.
- Preserve `--port` and `--open` for UI modes; reject incompatible flag combinations.
- Add server redirects for legacy navigational task URLs such as `/task/PM-0001` to `/tasks/PM-0001`.
- Keep ordinary .NET builds independent of Node. Release/publish workflows build Angular first and then embed its output.

## Acceptance

- Tests cover flag behavior, missing assets, static assets, SPA fallback, API exclusion, redirects, and browser opening.
- `pm web --api` works without Angular assets.
- Production Angular mode requires no adjacent web directory or CDN access.
