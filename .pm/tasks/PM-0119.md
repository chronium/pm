## Goal

Implement the reusable `chronium/pm` Action wrapper and safely dispatch its controlled command vocabulary to the pinned PM runtime.

## Implement

- Add the root Action metadata and entrypoint defined by the approved contract.
- Parse GitHub Action inputs as data without shell evaluation.
- Allow only `doctor`, `site-build`, and `version`; reject unknown commands before invoking PM.
- Resolve the selected project beneath `GITHUB_WORKSPACE` and reject traversal, symlink escapes, and invalid working directories.
- Map `doctor` and `version` to their exact PM CLI invocations.
- Preserve PM standard output, standard error, and process exit status.
- Publish documented Action outputs and concise job summaries where applicable.
- Add integration fixtures for default inputs, nested PM projects, invalid commands, unsafe paths, and failing doctor results.

## Acceptance criteria

- The proposed Action usage with `command: doctor` validates a checked-out project.
- Validation failures fail the Action step with the original PM diagnostic context.
- Unknown or unsafe input cannot become an additional command or shell fragment.
- The Action runs the digest-pinned runtime rather than building PM in the consumer repository.
- Tests cover success, validation failure, input rejection, and exit-code propagation.
