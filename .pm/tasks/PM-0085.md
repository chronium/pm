Follow the Milestone Deliverables and Activation Triggers architecture wiki entry.

Introduce the lifecycle mutation layer that creates automatic activation records when task completion or milestone delivery satisfies inactive triggers.

Acceptance criteria:
- Moving a task to done evaluates only affected inactive triggers.
- Delivering a milestone evaluates triggers that require it.
- Cascaded eligibility changes are visible in the authoritative mutation result.
- Task state, milestone delivery, and activation writes use bounded rollback or an equivalent recoverable transaction.
- Reopening tasks or milestones never removes activation records automatically.
- Failure injection tests prove state and provenance are not left partially updated.
