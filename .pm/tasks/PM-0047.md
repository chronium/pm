## Goal

Create the permanent Angular routing/layout foundation and PM visual system.

## Implementation

- Make `app.ts` own the shared top bar and one router outlet.
- Define an `AppShell` enum in parent route data. Route `/tasks` through `TasksShell` and `/wiki` through `WikiShell`; each shell owns its sidebar and child outlet.
- Add a small layout/navigation service exposing the active shell as a read-only signal for shared top-bar context. The router, not a template switch, selects shell components.
- Redirect `/` to `/tasks`; reserve top-bar structure for future search without displaying a nonfunctional search control.
- Create plain global CSS tokens for color, spacing, typography, radii, borders, elevation, focus, and motion. Support light/dark themes from system preference with a persisted user override.
- Use Oat CSS as a semantic baseline with no Oat JavaScript. Build a Linear-inspired PM identity: dense information, restrained surfaces, crisp borders, quiet metadata, and no Material styling.
- Use native semantic controls and dialogs first. Add no Angular Material dependency and no CDK dependency without a concrete behavioral need.
- Add reusable loading, empty, error, button, form-field, badge, and destructive-confirmation primitives.
- Preserve keyboard focus, reduced motion, responsive behavior, and accessible names from the start.
- Keep tokens compatible with a future Tailwind mapping through global CSS custom properties.

## Acceptance

- Root/tasks/wiki routing and active top-bar mode work on direct navigation and refresh.
- Both themes meet contrast expectations and persist correctly.
- Shells remain visually coherent at desktop and mobile widths.
- No page or API behavior is implemented inside presentation primitives.
