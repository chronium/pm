## Goal

Create a stable JSON adapter over the existing application services without introducing a second domain/service layer.

## Implementation

- Add a loopback-only `/api/v1` endpoint group, split by feature rather than extending the current monolithic web endpoint class.
- Define explicit API request/response DTOs; do not serialize application records as the public wire contract.
- Use camelCase JSON and UTC ISO-8601 timestamps.
- Map `AppResult` failures to RFC Problem Details with a stable PM error code extension and appropriate HTTP status.
- Accept mutation bodies as JSON only. Require a non-simple PM client header on writes and configure no cross-origin access; Angular development uses the same-origin proxy.
- Publish an OpenAPI document and generate TypeScript contract types only. Keep the Angular API client handwritten so it can use signals, `httpResource`, and `HttpClient` idiomatically.
- Add a minimal project metadata/readiness endpoint that proves the API and generated types work.
- Keep all business behavior in `BoardService`, `TaskService`, `WikiService`, `ProjectConfigService`, and `ProjectValidationService`.

## Acceptance

- API success and failure shapes are covered by xUnit contract tests.
- Generated TypeScript types are reproducible and checked for drift.
- No CORS policy exposes the local API to arbitrary origins.
- Existing CLI, MCP, and htmx behavior remains unchanged.
