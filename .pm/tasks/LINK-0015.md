## Goal

Expose linked-project manifest mutations through the CLI so users can configure reciprocal parent and child declarations without editing `.pm/linked_projects.yaml` by hand.

## Proposed implementation

- Add CLI commands for setting and removing a project's parent declaration.
- Add CLI commands for adding, updating, removing, and reordering child declarations.
- Accept the complete declaration metadata: stable project ID, alias, repository URL, optional relative `pathHint`, and optional `publicSiteUrl`.
- Route every command through the existing `LinkedProjectService` mutation methods so validation, deterministic serialization, ordering, and deletion of an empty manifest remain centralized.
- Keep command output concise and identify the declaration that changed.
- Update the linked-project setup guide so step 3 uses CLI examples for both the parent repository and each child.
- Preserve direct YAML authoring as a supported human-readable escape hatch, but make it unnecessary for normal family setup.

## Suggested command surface

```sh
pm project set-parent <project-id> --alias <alias> --repository <url> [--path <path>] [--public-site <url>]
pm project remove-parent

pm project add-child <project-id> --alias <alias> --repository <url> [--path <path>] [--public-site <url>]
pm project update-child <project-id> [declaration options]
pm project remove-child <project-id>
pm project reorder-children <project-id>...
```

Final command names and option spelling should follow the existing Spectre.Console CLI conventions.

## Acceptance criteria

- A parent repository can add, update, remove, and reorder child declarations entirely through the CLI.
- A child repository can set, update, and remove its parent declaration entirely through the CLI.
- Commands reject invalid IDs, aliases, repository URLs, path hints, duplicate declarations, self-references, and invalid child orders using existing service errors.
- Optional values can be explicitly cleared when updating a declaration.
- Commands preserve deterministic YAML and remove `.pm/linked_projects.yaml` when its final declaration is removed.
- Command behavior tests cover successful setup, updates, removals, reordering, validation failures, and useful console output.
- The linked-project guide includes a complete reciprocal parent/two-child setup example using the new commands.
- `pm doctor` validates the generated family without requiring manual metadata repair.
