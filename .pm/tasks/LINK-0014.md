## Goal

Prove the linked-project model against a parent Games repository containing Royale and a second game as Git submodules.

## Proposed implementation

- Build fixtures for parent, child, sibling, standalone child clone, missing child, and uninitialized submodule states.
- Exercise CLI, MCP, API, Angular switching, cross-project dependencies, wiki links, trust-controlled writes, static links, and agent context preflight.
- Verify current-working-tree reads, active-project ranking preference, and exact project ownership in every result.
- Confirm no initial workflow coordinates writes across repositories.

## Acceptance criteria

- The complete intended scenario works on desktop and mobile.
- Every unavailable-project case leaves the active project usable.
- Doctor provides actionable warnings including the submodule initialization command.
- Documentation gives a concise setup and recovery walkthrough.
