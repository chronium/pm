## Goal

Make task search use the current Angular sidebar scope by default, while keeping project-wide search available through an explicit query predicate. Remove the board status filter toolbar so it no longer consumes task-board space.

## Proposed implementation

- Treat the selected sidebar scope—whole project, one milestone, or one track—as the implicit boundary for task search.
- Add an `in:` search predicate with the accepted values `selection` and `all`.
- Interpret `in:selection` as the default when the predicate is omitted.
- Let `in:all` search the whole project regardless of the selected sidebar track or milestone.
- Keep existing search predicates, including `state:`, composable with the new search boundary.
- Remove the board-level status filter component and toolbar from the Angular task board.
- Stop using the board `state` query parameter as a visible filtering control; preserve compatible deep-link behavior only where it remains necessary during the transition.
- Ensure selecting a search result preserves the active sidebar scope and returns to that scope when the task dialog closes.
- Keep search result loading, empty, error, keyboard, and mobile behavior accessible and compact.
- Update API/query parsing, generated OpenAPI types, Angular search coordination, tests, stories, and E2E workflows as needed.
- Do not introduce a replacement filter bar or a broader filtering system in this task.

## Acceptance criteria

- With a track selected in the sidebar, a search without `in:` returns matches only from that track.
- With a milestone selected in the sidebar, a search without `in:` returns matches only from that milestone.
- With All tasks selected, implicit selection search covers the whole project.
- `in:selection` behaves identically to the implicit default.
- `in:all` returns project-wide matches from any sidebar scope.
- `in:` rejects missing or unsupported values with the standard structured query error.
- `state:<key>` can be used in search and composes with both `in:selection` and `in:all`.
- Search navigation and task-dialog close behavior retain the sidebar selection.
- The status filter toolbar is absent from the task board on desktop and mobile.
- Removing the toolbar does not restyle task rows, milestone sections, state groups, or board surfaces.
- Relevant service, API, Angular component/integration, Storybook, and desktop/mobile E2E tests cover the new behavior.
