## Goal

Create CLI and web analogs for the planned `get_next_task` MCP workflow so all modes can surface the next recommended task.

## Proposed implementation

- After the core recommendation service exists, add `pm next` or `pm task next` with optional track filter.
- Add a quiet Next task affordance in the web task board, likely near the task sidebar/header.
- Use the same recommendation service as MCP.
- Show why the task was selected when practical.

## Acceptance criteria

- CLI and web return the same recommended task for the same filters.
- Empty/no-actionable states are handled cleanly.
- Optional track filtering behaves consistently across modes.
- Bulk behavior remains out of scope.

## Validation notes

- Add command, endpoint, and renderer tests after `get_next_task` core service exists.
- Run .NET build and tests.
