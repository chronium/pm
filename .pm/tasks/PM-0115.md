## Goal

Expose the shared delivered-work visibility choice consistently through live, linked-project, and static-site HTTP reads without discarding published history.

## Proposed implementation

- Add an optional `includeDelivered=false` query parameter to board, board-navigation, and task-search endpoints, including selected linked-project routes.
- Include the visibility choice in the typed board filter contract and generated Angular API types where appropriate.
- Forward the option into the shared board and search services before response shaping, enrichment, revision handling, and pagination.
- Keep static snapshots complete rather than baking the default filter into exported data.
- Update the static snapshot adapter to filter milestone navigation, board groups, tasks, counts, and search results locally from the request option.
- Preserve direct task lookup in static exports even when its milestone is hidden from discovery.
- Keep existing snapshots and clients compatible when the new option is absent.

## Acceptance criteria

- Live and linked API reads hide delivered work when the query parameter is absent or false.
- `includeDelivered=true` restores delivered milestones and tasks in board, navigation, and search responses.
- Static exports exhibit the same behavior without a backend and without dropping delivered task detail data.
- Navigation and board counts describe the same visible task set.
- Existing project data, direct task URLs, and older clients continue to work.
- API schemas and generated Angular contracts are current.
- Focused API, snapshot, and static-mode tests cover defaults, opt-in recovery, accepted unfinished tasks, and reopening.
- Relevant .NET and Angular validation passes.
