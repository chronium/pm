Follow the Milestone Deliverables and Activation Triggers architecture wiki entry.

Implement a pure application-layer resolver for current requirement satisfaction, latched trigger state, consuming milestones, and milestone lifecycle.

Acceptance criteria:
- Empty requirement lists are not vacuously satisfied.
- Task requirements use the current done state.
- Milestone requirements use the presence of a valid delivery record.
- Trigger activity depends only on an activation record.
- Resolved results retain current counts separately from activation provenance.
- Milestone precedence is Delivered, Inactive, Ready to deliver, then Active.
- Empty milestones are Active rather than Ready to deliver.
- Resolver tests cover latched automatic and override states after requirements change.
