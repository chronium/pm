## Priority

Top priority for agent workflow.

## Goal

Return the next recommended task to work on so agents do not have to infer priority from `list_tasks`.

## Proposed implementation

- Add a service method that selects the next task using state order, milestone order, stored task order, modified time fallback, and optional track filtering.
- Prefer actionable states before completed states.
- Expose the result through an MCP `get_next_task` tool with a structured task payload and the reason it was selected.
- Keep the selection deterministic when multiple tasks have the same priority.

## Acceptance criteria

- Agents can request one recommended task without reading the full board.
- Optional track filtering narrows the candidate set.
- Stored task order is respected when available.
- Empty/no-actionable states return a stable empty result rather than an arbitrary task.

## Validation notes

- Add service and MCP tests for state ordering, milestone grouping, task order, track filtering, and empty results.
