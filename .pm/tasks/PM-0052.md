## Goal

Replace the current settings page using the project settings and validation APIs.

## Implementation

- Add project settings as `/tasks/settings` under `TasksShell`; redirect legacy `/settings` navigation to it.
- Use a feature store with signals and `httpResource`; use Angular 22 Signal Forms for create/rename/priority controls.
- Implement status, track, and milestone creation, rename, removal, and milestone-priority updates.
- Apply the project-config ETag to every settings mutation and refresh settings/validation immediately after success.
- Make in-use and last-item restrictions visible through returned service errors without duplicating domain validation in Angular.
- Render project validation as a dense structured summary with useful object/path context.
- Keep destructive actions contextual, confirmed, keyboard-accessible, and disabled while pending.
- Handle loading, empty, success, stale, and server-validation states without layout shifts.

## Acceptance

- Every current settings workflow reaches the same service behavior as CLI/MCP.
- Stale config writes cannot silently overwrite newer settings.
- Long keys/titles do not overlap controls at supported widths.
- Vitest and Playwright cover representative success, restriction, and conflict flows.
