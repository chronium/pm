## Goal

Add the approved `site:` configuration to the structured project model and make every PM config read and write preserve it safely.

## Implement

- Add typed site, home-composition, and closed section models for `single` and `split` layouts.
- Omitted `site` preserves existing behavior; omitted `layout` means `single`; omitted single `sections` expands to hero, milestone, tasks, and wiki.
- Validate required and forbidden region fields, exactly-one-first hero placement, optional-final copyright placement, section-specific fields, references, task filters, limits, and unknown fields.
- Validate disabled retained configuration as well as enabled configuration.
- Keep absent `site` omitted during unrelated config serialization; round-trip an explicitly disabled site without churn.
- Report deterministic actionable issues through project validation and doctor.

## Compatibility

No project-data migration is required. Existing projects without `site` must read, mutate, and serialize unchanged. Do not retain a parallel legacy Overview model because no released consumer exists.

## Acceptance

Focused ProjectConfig, serialization, migration-compatibility, and validation tests cover implicit, single, split, copyright, invalid union, dormant, and absent-site cases. Run the .NET build and test gates.
