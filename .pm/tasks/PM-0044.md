## Goal

Expose the current wiki tree, folder, page, editing, metadata, and removal workflows through `/api/v1`.

## Implementation

- Add endpoints to list wiki pages, read a page, create a page, update body-only Markdown, rename path/title metadata, and delete a page.
- Preserve slash-delimited wiki paths safely through URL encoding and the existing `ProjectRoot` path validation.
- Return enough summary data for Angular to construct the full folder/page tree client-side.
- Represent folders as derived navigation nodes, not persisted wiki resources.
- Apply page ETags to body edits, metadata edits, and deletion.
- Keep frontmatter internal: create accepts path/title/body, body edit accepts body only, and metadata editing has explicit path/title fields.
- Reuse `WikiService`; MCP outline/patch operations are not part of current web parity.
- Return stable Problem Details for invalid paths, duplicates, missing pages, invalid Markdown, and stale revisions.

## Acceptance

- Tests cover list/tree input, folders, reads, create, body update, rename, delete, path escaping, and ETag failures.
- A folder path with no page but with descendants is represented successfully.
- API responses never expose unsanitized rendered HTML; rendering remains a frontend responsibility.
