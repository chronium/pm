## Goal

Freeze the supported public contract for invoking Project Model from GitHub Actions before implementing its container wrapper.

## Design

- Define the root `chronium/pm@<ref>` Action identity as a Docker Action for GitHub-hosted Linux runners.
- Require an explicit `command` from the initial allowlist: `doctor`, `site-build`, and `version`.
- Define `working-directory` relative to the workspace root, defaulting to `.`.
- Define `output-directory` relative to the workspace root, defaulting to `dist/pm-site`.
- Preserve PM's existing non-destructive output behavior unless `force: true` is supplied explicitly.
- Omit base-path configuration because current static exports already use relative assets and hash routing.
- Return `pm-version` for successful commands and `site-path` for successful site builds.
- Preserve native PM diagnostics and exit codes without adding structured annotations in v1.
- Require canonical project and output paths to remain within `GITHUB_WORKSPACE`.
- Pass declared inputs as fixed container arguments without shell evaluation or unrestricted CLI passthrough.
- Define `latest`, compatible-major, immutable-version, and SHA consumption guidance.
- Require released Action metadata to select a tested immutable OCI image digest through an authorized signed promotion commit.
- Keep artifact upload and hosting deployment outside the Action.
- Exclude mutation commands, `doctor --fix`, and repository write-back from v1.

## Acceptance criteria

- A versioned repository contract contains the complete proposed `action.yml` interface and consumer examples.
- Every initial command has unambiguous inputs, outputs, side effects, path rules, and exit behavior.
- Version/ref behavior distinguishes coordinated `@latest` consumers from stable third-party consumption.
- The design explains how the Action and OCI runtime are promoted as one tested release without unsigned generated commits on `main`.
- Follow-up implementation tasks can proceed without inventing additional public semantics.
