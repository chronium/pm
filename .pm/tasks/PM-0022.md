## Goal

Report orphaned or repairable project data issues in a focused form for agent repair workflows.

## Proposed implementation

- Build on `ProjectValidationService` but return a repair-oriented subset/grouping.
- Include orphaned task files, broken state refs, invalid wiki frontmatter, stale task order entries, and unknown track/milestone/status references.
- Keep this read-only; repairs should be handled by explicit mutation tools.
- Expose through MCP as `list_orphaned_items`.

## Acceptance criteria

- Agents can list repair targets without parsing full validation output.
- Results include type, path, affected ID/path, and suggested repair direction.
- Empty result indicates no known orphaned items.
- `validate_project` remains the broader health check.

## Validation notes

- Add service and MCP tests using broken refs, stale task order, invalid wiki markdown, and unknown metadata references.
