## Goal

Let users switch between independently rendered family projects while preserving clear ownership and current-project context.

## Proposed implementation

- Add project-qualified API routes and a project selector in the shared top bar.
- Show the parent and ordered children as a compact family hierarchy.
- Keep task and wiki shells independent for the selected project.
- Preserve filters and routes per project where practical.
- Display unavailable family members as disabled entries with resolution guidance.
- Avoid an aggregate board in this slice.

## Acceptance criteria

- Switching projects changes the URL and active API context.
- Every task and wiki view clearly identifies its owning project.
- Standalone projects retain the current shell with no empty project chrome.
- Desktop and mobile navigation remain accessible and responsive.
