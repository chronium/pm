## Goal

Avoid inflated `search_tasks` match counts caused by counting both semantic fields and the full markdown representation for the same text.

## Proposed implementation

- Review how `TaskService.SearchTasks` builds searchable fields.
- Keep broad search coverage across metadata, body, dependencies, and markdown/frontmatter.
- Adjust match counting so relevance is useful without double-counting the same content excessively.
- Preserve deterministic ordering and existing snippets.

## Acceptance criteria

- `matchCount` remains deterministic and useful for ranking.
- Metadata-only and body-only matches are still found.
- Full markdown/frontmatter-only terms such as `dependsOn:` remain searchable.
- Tests cover the refined counting behavior.
