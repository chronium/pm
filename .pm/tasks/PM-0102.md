## Goal

Allow trusted MCP clients to operate activation trigger transitions in a selected write-trusted linked project while preserving latching, provenance, revisions, and recovery semantics.

## Scope

- Add an optional `project` selector to `activate_activation_trigger`, `override_activation_trigger`, `reset_activation_trigger`, and `reconcile_activation_triggers`.
- Add the selector to `preview_activation_trigger_redefinition` and `redefine_activation_trigger`.
- Evaluate requirements, waived-requirement snapshots, reset guards, lifecycle impact, and automatic activation exclusively against the selected project.
- Bind redefinition revisions to the selected project's configuration so a preview from one project cannot authorize a mutation in another.
- Preserve dry-run reconciliation as read-only with no mutation receipt; applied reconciliation returns target-owned paths.
- Return the selected project's authoritative switchboard after successful mutations and include target identity in every receipt.
- Keep every lifecycle control unavailable to run-worker MCP profiles, even when `project` is omitted or `current`.
- Remove superseded active-project-only lifecycle adapters.

## Acceptance criteria

- Manual activation, override, reset, redefine preview/apply, and reconciliation work by alias, stable ID, and `parent` for write-trusted projects.
- Untrusted or unavailable targets fail without changing either repository.
- Reset and redefine guards use the selected project's current requirements and lifecycle.
- Preview revisions are rejected when stale or produced for a different project.
- Override provenance and waived requirements are captured from the target project only.
- Mutation receipts agree with an immediate selected-project switchboard reread.
- Reconciliation never deactivates a trigger and dry-run never writes.
- Focused service and stdio MCP tests cover success, stale revisions, trust denial, project isolation, dry-run behavior, receipts, and run-worker denial.

## Out of scope

Milestone delivery and reopening are handled separately.
