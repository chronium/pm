## Goal

Bring linked-project reads to CLI and MCP without burdening normal local workflows.

## Proposed implementation

- Add an optional project selector to existing task and wiki read tools and commands.
- Add explicit family scope where aggregation is meaningful.
- Include project ID, alias, name, revision, and warnings in cross-project responses.
- Preserve current-project defaults when the selector is omitted.
- Keep bulk cross-project operations out of CLI and keep run-worker MCP authority constrained.

## Acceptance criteria

- Existing command lines and MCP requests remain compatible.
- Explicit selectors resolve parent, child, and sibling targets.
- Unknown or unavailable selectors return actionable errors.
- MCP schemas describe accepted project selector forms.
