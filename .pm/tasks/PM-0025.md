## Goal

Show project validation status in the web UI so users can spot broken refs, invalid markdown, and stale ordering without using MCP.

## Proposed implementation

- Add a project health section to settings or a small dedicated web page.
- Use `ProjectValidationService.ValidateProject`.
- Render grouped issues with severity, code, message, and relevant object/path metadata.
- Keep the surface read-only; repairs remain explicit actions elsewhere.

## Acceptance criteria

- Settings or project health page shows valid/invalid status.
- Validation issues are escaped and readable.
- Empty/valid state is quiet and not visually noisy.
- MCP `validate_project` behavior remains unchanged.

## Validation notes

- Add renderer and endpoint tests for valid and invalid validation results.
- Run .NET build and tests.
