## Goal

Expose milestone delivery and reopening as guarded Angular control-plane actions so operators do not need to leave the web workspace for the final deliverable lifecycle transition.

## Scope

- Add contextual Deliver and Reopen actions to the milestone deliverable experience without competing with the deliverable content.
- Use the existing delivery preview and revisioned mutation APIs.
- Present ordinary delivery directly and require an explicit reason plus confirmation for exceptional delivery with unfinished tasks.
- Show the accepted unfinished-task snapshot before confirmation and preserve returned delivery provenance after mutation.
- Handle stale revisions, loading, validation, permission-restricted, read-only, and error states.
- Refresh board, milestone lifecycle, recommendation eligibility, and activation state after delivery or reopening.

## Acceptance criteria

- Ordinary and exceptional delivery use the server preview revision and cannot bypass required confirmation.
- Reopening removes delivery provenance and immediately re-evaluates current activation gates.
- Controls are keyboard accessible, use existing dialog and surface patterns, and remain hidden for read-only projects and static exports.
- Focused component, Storybook, API-store, and hosted browser tests cover delivery, exceptional confirmation, reopening, conflicts, and failures.
