## Goal

Expose current project settings and project validation workflows through the versioned API.

## Implementation

- Add settings and validation read endpoints.
- Add status, track, and milestone creation, rename, and removal endpoints plus milestone-priority updates.
- Use one project-config ETag for settings mutations and return the updated settings representation and revision after success.
- Preserve current restrictions: last status/track cannot be removed, in-use items cannot be removed, status directories must be safe to delete, and priority values use existing normalization.
- Keep validation read-only and return structured issue data suitable for an Angular summary.
- Reuse `ProjectConfigService` and `ProjectValidationService`; do not duplicate configuration rules in endpoint handlers.

## Acceptance

- Endpoint tests cover every mutation, restriction, stale config revision, and validation result.
- Error codes/messages remain consistent with CLI and MCP service behavior.
- The API does not expose bulk settings operations.
