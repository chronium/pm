## Goal

Allow application services to read tasks and wiki pages from one explicitly selected linked project or the available project family.

## Proposed implementation

- Introduce project-context creation around resolved project roots while reusing existing task, board, config, and wiki services.
- Support current, explicit project, and family read scopes.
- Return owning project identity and resolution warnings with every federated result.
- Use current working-tree contents and expose Git revision and dirty state as context.
- Bound traversal and result sizes, with cancellable live queries and no persistent shared index initially.

## Acceptance criteria

- List, get, and search work across available linked projects.
- Current-project reads retain their existing fast path.
- Unavailable projects produce partial results rather than total failure.
- No read path mutates or registers write trust for another project.
