## Goal

Replace separate task read and edit modes with one inline-editing workspace shared by routed dialog and full-page hosts.

## Scope

- Keep `/tasks/:taskId` and `/tasks/new` as canonical full pages, with internal desktop overlay routes nested over the board.
- Preserve canonical anchor links while intercepting normal desktop activation for routed dialogs; use full pages for mobile, direct, and modified navigation.
- Share loading, polling, drafts, validation, conflicts, saving, removal, and content layout between thin dialog and page hosts.
- Edit title, status, track, milestone, priority, and description inline with one active field and one accumulated draft.
- Derive dirty state from actual draft differences and preserve drafts through validation and conflict review.
- Reuse the workspace for creation, keeping initial status and priority as read-only defaults.
- Refresh mounted task navigation and boards through navigation signals rather than injecting board state into detail behavior.
- Keep the responsive workspace dense, accessible, full width on pages, and contained in a wider dialog.

## Acceptance

- Desktop board activation opens an overlay without changing canonical link targets; mobile and direct navigation use full pages.
- Fullscreen, Back, Close, Save and close, and Create and close preserve a validated scoped return URL.
- Inline fields remain dimensionally stable, retain accumulated changes, and expose semantic accessible controls.
- Save persists the complete draft, Cancel restores the accepted task, and navigation protects unsaved changes.
- Creation transitions to saved detail in the same host and removal returns to the originating board scope.
- Dialog, page, creation, long-content, dark, mobile, and active-field states have automated coverage.

## Out of scope

- Backend task API changes, new task metadata fields, and broad task-board restyling.
