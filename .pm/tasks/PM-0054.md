## Goal

Validate full parity, establish repeatable release builds, and make Angular the default PM web interface.

## Implementation

- Add focused Playwright end-to-end coverage for startup/routing, filters, task create/open/edit/state/remove/conflict, wiki tree/create/edit/rename/delete, settings restrictions, theme persistence, and legacy redirects.
- Keep Angular unit/component coverage in Vitest, API contracts in xUnit, and component interaction/accessibility checks in Storybook.
- Add documented scripts for Angular build/test, Storybook build/checks, Playwright, .NET build/test, and combined release validation.
- Make the release/publish sequence run dependency installation through Socket when needed, build Angular, verify generated OpenAPI types, embed the browser assets, then build/publish .NET.
- Add reasonable Angular bundle budgets and verify PM runs without CDN/network access.
- Exercise the UI against a realistic large fixture comparable to the 170-task project and a multi-page wiki.
- Switch `pm web` and `pm web --ui angular` to Angular by default while retaining `--ui legacy` for one stability release.
- Update README and repository instructions for development, testing, packaging, troubleshooting, and the temporary legacy escape hatch.
- Do not remove the legacy renderer/templates in this task; schedule removal after the stability release.

## Acceptance

- All frontend, Storybook, API, and .NET checks pass from documented commands.
- Production `pm web` serves the embedded Angular app and JSON API from one loopback origin.
- `pm web --api` supports the two-terminal development workflow.
- Current web workflows have accepted behavioral parity and legacy remains available for fallback.
