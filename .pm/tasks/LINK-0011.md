## Goal

Allow deliberate mutations of one linked project while preventing filesystem proximity from granting authority.

## Proposed implementation

- Store project-level write trust in private user configuration.
- Add commands and settings UI to grant, inspect, and revoke trust.
- Add optional project selection to supported task and wiki mutation services.
- Resolve and authorize the complete target before writing.
- Limit each operation to one repository and return the changed project and paths.
- Keep run-worker MCP cross-project writes disabled.

## Acceptance criteria

- Linked projects are read-only until explicitly trusted.
- Writes to unavailable, mismatched, or untrusted projects fail without local changes.
- Existing active-project mutations require no new confirmation.
- CLI, MCP, API, and web enforce the same trust result.
