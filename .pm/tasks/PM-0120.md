## Goal

Make `command: site-build` a complete reusable static-publishing primitive for PM repositories.

## Implement

- Translate typed project, output, and optional base-path inputs into the established PM static-export workflow.
- Default the project to the checked-out workspace and the output to a documented workspace-relative directory.
- Reject output paths outside `GITHUB_WORKSPACE` and prevent accidental project-state mutation.
- Preserve complete static snapshot data, configured Overview content, accents, wiki content, search, and linked-project navigation metadata.
- Return the generated site path and useful build metadata as Action outputs.
- Support repeated invocations for separately published projects in one linked family without output collisions.
- Document composition with GitHub Pages artifact upload/deployment and generic artifact upload.

## Acceptance criteria

- A consumer can generate a deployable site with only checkout plus `chronium/pm`.
- Generated output is behaviorally equivalent to the supported local static build.
- Nested and repeated project builds produce deterministic, isolated output directories.
- Base-path routing and linked project-switcher URLs work in disposable static-site smoke coverage.
- The Action does not take deployment permissions or deploy the output itself.
