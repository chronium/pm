## Goal

Make `command: site-build` a complete reusable static-publishing primitive for PM repositories.

## Implement

- Translate the approved `working-directory`, `output-directory`, and `force` inputs into the established PM static-export workflow.
- Default the project to the checked-out workspace and the output to the documented workspace-relative directory.
- Reject output paths outside `GITHUB_WORKSPACE` and prove that site export does not mutate project state.
- Preserve complete static snapshot data, configured Overview content, accents, wiki content, search, and linked-project navigation metadata.
- Return the approved `pm-version` and `site-path` Action outputs.
- Support repeated invocations for separately published projects in one linked family without output collisions.
- Prove nested hosting through the existing relative-assets and hash-routing contract; do not add a base-path input.
- Document composition with GitHub Pages artifact upload/deployment and generic artifact upload.

## Acceptance criteria

- A consumer can generate a deployable site with only checkout plus `chronium/pm`.
- Generated output is behaviorally equivalent to the supported local static build, excluding the intentional generation timestamp.
- Nested and repeated project builds produce deterministic, isolated output directories.
- Nested hosting and linked project-switcher URLs work in disposable static-site smoke coverage.
- The Action exposes only the approved four inputs and two outputs.
- The Action does not take deployment permissions or deploy the output itself.
